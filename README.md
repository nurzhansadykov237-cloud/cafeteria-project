# Столовая: меню и предзаказ

**Вариант 22 — учебный Django-проект**

## 1. Описание проекта

«Столовая: меню и предзаказ» — веб-приложение для управления меню столовой и оформления предварительных заказов.

Пользователи могут просматривать доступные блюда, искать их по названию, фильтровать по категориям, добавлять в корзину и оформлять заказы.

Сотрудники столовой и администраторы могут управлять блюдами, просматривать заказы и статистику.

Основная цель проекта — автоматизировать работу с меню, корзиной и предварительными заказами.

## 2. Используемые технологии

- Python 3.14
- Django 6.1
- SQLite — база данных
- Django REST Framework — создание REST API
- drf-yasg — документация API (Swagger и ReDoc)
- Bootstrap 5 — оформление интерфейса
- HTML / CSS — структура и стили страниц
- openpyxl — экспорт данных в Excel
- python-dotenv — загрузка переменных окружения
- Git и GitHub — контроль версий и хранение исходного кода
- WSL Ubuntu — дополнительная среда разработки и запуска проекта

## 4. Роли и права пользователей

В проекте предусмотрено разделение доступа.

- **Администратор** — управление приложением через административную панель Django, управление данными и доступ к административным функциям.
- **Сотрудник столовой** — работа с блюдами и просмотр доступных сотрудникам разделов, включая статистику.
- **Клиент** — просмотр меню, добавление блюд в корзину и оформление заказов.

Доступ к отдельным страницам и операциям ограничивается средствами авторизации и проверки прав пользователей.

## 6. Установка и запуск проекта

### 6.1. Клонирование репозитория

```bash
git clone https://github.com/nurzhansadykov237-cloud/cafeteria-project.git
```

Перейти в папку проекта:

```cmd
cd cafeteria-project
```

### 6.2. Создание виртуального окружения

```cmd
py -m venv venv
```

Активировать окружение:

```cmd
venv\Scripts\activate
```

### 6.3. Установка зависимостей

```cmd
pip install -r requirements.txt
```

### 6.4. Настройка переменных окружения

В корневой папке проекта необходимо создать файл `.env`:

```env
SECRET_KEY=ваш_секретный_ключ
DEBUG=True
```

Для генерации секретного ключа можно выполнить команду:

```cmd
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Полученный ключ необходимо вставить в `.env` вместо `ваш_секретный_ключ`.

**Важно:** файл `.env` содержит секретные настройки и не должен публиковаться на GitHub.

### 6.5. Подготовка базы данных

Выполнить миграции:

```cmd
python manage.py migrate
```

Загрузить начальные данные:

```cmd
python manage.py loaddata core/fixtures/seed_data.json
```

Команда загружает подготовленные записи категорий, блюд и меню дня.

### 6.6. Создание администратора

```cmd
python manage.py createsuperuser
```

Следовать инструкциям Django для создания учётной записи администратора.

### 6.7. Запуск сервера

```cmd
python manage.py runserver
```

Открыть приложение в браузере:

`http://127.0.0.1:8000/`

### 6.8. Запуск в WSL Ubuntu

После установки WSL Ubuntu и создания Linux-виртуального окружения можно использовать следующие команды из папки проекта:

```bash
source .venv-linux/bin/activate
```

Проверка проекта:

```bash
python manage.py check
```

Запуск сервера:

```bash
python manage.py runserver 0.0.0.0:8001
```

Открыть приложение:

`http://127.0.0.1:8001/`

## 7. API и документация

В проекте реализован REST API на основе Django REST Framework.

Основные адреса:

- API: `http://127.0.0.1:8000/api/`

API предоставляет интерфейс для взаимодействия с данными приложения.

Для отдельных операций предусмотрены проверки авторизации и прав доступа.

Swagger и ReDoc позволяют просматривать описание доступных API-операций и проверять запросы.

## 9. Структура проекта и назначение модулей

### 9.1. Основная конфигурация

- `config/settings.py` — настройки Django, подключённые приложения, база данных, безопасность и другие параметры.
- `config/urls.py` — основные маршруты проекта.
- `config/wsgi.py` — точка входа WSGI.
- `config/asgi.py` — точка входа ASGI.

### 9.2. Основное приложение core

- `core/models.py` — модели базы данных: категории, блюда, меню дня, заказы и позиции заказа.
- `core/views.py` — обработка запросов, отображение страниц, работа с корзиной, оформление заказов и статистика.
- `core/forms.py` — формы приложения и проверка вводимых данных.
- `core/urls.py` — маршруты основного приложения.
- `core/admin.py` — регистрация моделей в административной панели и дополнительные действия, включая экспорт в Excel.
- `core/tests.py` — автоматические тесты моделей, форм, представлений, API и корзины.

### 9.3. API

- `core/serializers.py` — сериализаторы для преобразования данных моделей в формат REST API и проверки входящих данных.
- `core/api_urls.py` — настройка маршрутов API с помощью `DefaultRouter`.
- `core/views.py` — содержит представления API: `DishViewSet`, `DailyMenuViewSet` и `OrderViewSet`.

API предоставляет операции для работы с блюдами, меню дня и заказами.

### 9.4. Шаблоны и данные

- `core/templates/core/` — HTML-шаблоны страниц приложения.
- `core/migrations/` — миграции структуры базы данных.
- `core/fixtures/seed_data.json` — подготовленные начальные данные проекта.

### 9.5. Документация и вспомогательные файлы

- `docs/` — документация и схемы проекта.
- `docs/ER_DIAGRAM.md` — схема сущностей базы данных.
- `docs/ORDER_FLOWCHART.md` — схема процесса оформления заказа.
- `requirements.txt` — список зависимостей Python.
- `.env` — локальные настройки и секретный ключ.
- `.gitignore` — список файлов, исключённых из Git.
- `logs/` — журналы приложения.
- `BUGFIXES.md` — описание исправленных ошибок.
- `manage.py` — управление Django-проектом.
